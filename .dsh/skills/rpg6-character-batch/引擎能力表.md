## 常见缺口（分诊会标出来，逐条确认能否用现有组合近似）

- 复活/免死、状态快照或回到第 N 回合、每回合额外行动
- 依赖场外行为的判定（喊数字、对方回答）、需要对方逐回合输入的交互
- 按次数反弹；需要关闭已挂持续效果的入口（「可停止」）
- 公式里读「本次伤害值」的表达式（`evalValue` 没有 `amount`）

护盾、免击溃/免异常/蓄力不断、法伤专属易伤、伤害转血上限、群攻上限、`{summonCount}`、额外动作、`untilRecast` 已在第六/七批落地，见上面的 op 表。

## 计划文件与脚本

| 路径 | 用途 |
|---|---|
| `assets/plan.example.json` | 计划示例：字段写法、fixture 命名、`--check` 能通过的完整样例 |
| `scripts/lib.mjs` | 读 seed 与技能库、覆盖率计数、分诊、`eachOp` 递归找 summon.key |
| `scripts/inventory.mjs` | 盘点、缺口分诊、生成 plan 草稿：`--remaining`、`--character`、`--triage`、`--plan --fixture <拼音> --out plan.json` |
| `scripts/plan.mjs` | `--check` 校验并打印逐技能确认表、`--scaffold --write` 直接落盘；op/hook 名单从引擎现扫 |
| `scripts/verify.ps1` | 一条命令验收：plan → 引擎单测 → 冒烟 → `check.ps1`；`-Browser` 才跑浏览器组 |

`plan.mjs --write` 会改 `data/skills/*.js` 与 `index.js`（按四行 `RPG6-SCAFFOLD` 锚点插入），写机制文档一节（正文取 plan 的 `notes`）并写回文档计数；其余脚本只读源码。
