## 一、玩家视角

1. 选两名角色，填种子（留空则随机）。**速度低者先手**，同速在开局用种子随机决定。
2. 每个标准回合，角色速度条 +速度；累计满 100 就获得一次角色回合，每回合 1 点行动（爆发者 2 点）。
3. 行动可选：普攻、击溃、蓄蓝、释放技能。**蓄力**不是按钮——点一个蓄力不足的技能就是给它蓄力 1 点，消耗 1 行动。
   少数技能释放时要输入一个数值：田誉清的「霰弹枪」会弹出一个输入框，填要支付的蓝（1..当前蓝），确认后才结算。
4. 击溃：目标击溃值 ≥3 才可用，进入击溃后无法行动；**击溃期间击溃值固定为 0**，击溃结束从 0 重新累计。
5. 蓄蓝 +1 蓝；蓝与力都用于技能。力绑定单个技能，换技能蓄力会清零。
6. 打完弹出结果，战报自动入库；`?record=<id>` 可逐步回放，也能从任意一步「接着打」。中途刷新会提示「继续上一局」。

界面五块：左侧速度条预期（21 行，可折叠）、两块角色状态（状态带 + 可展开的伤害记录）、右上详情栏（悬停 Buff、持续效果或召唤物）、下方两个角色查询框（技能与基础操作）、底部战斗日志（可折叠）。有召唤物时，角色卡底部多一条召唤物带：有血的显示血量与剩余回合、可被单体选中，无血的用虚线只显示剩余回合；选择目标时可选召唤物会高亮，被嘲讽保护的目标会提示。悬停召唤物看详情：召唤者、剩余回合、六维当前值（没有面板的写「无面板」）、速度条进度、光环/到期/自动攻击的文案（`desc`，缺省时按脚本自动拼，拼不出来写「见技能说明」），以及它身上的 Buff、状态与标记；挂件标签也能悬停看单条说明。

**手机**：竖屏会被「请横屏」遮罩挡住，唯一入口是「横屏继续」——它请求全屏并尝试 `screen.orientation.lock("landscape")`；不支持锁方向（iOS 网页）时就只提示手动横过来。遮罩由 JS 判定（粗指针 + 有触摸 + 视口短边 ≤520）后才显示，桌面窄窗口、平板、鼠标设备都不弹。横屏下换紧凑布局：站点导航隐藏、速度条收成一行、双方状态与技能左右并排、页面不滚（各列内部滚动）、技能效果默认收起、Buff 与召唤物详情改为点图标弹气泡。召唤物带横向滚动不额外占高度；844×390 带墓的用例已断言一屏。

**折叠面板**：速度条预期桌面可折（展开只在原位铺开）；战斗日志桌面与手机都可折（点标题行折叠/展开）。桌面折叠时只显示上一个有效回合的日志行（不含「第 N 标准回合」分隔行），展开时高度与速度条面板对齐；手机横屏下速度条与战斗日志默认只占一行，展开后铺满视口、盖住其它内容（`position: fixed; inset: 0`，标题行 sticky 当关闭入口），长内容在面板内滚动。

**伤害记录**：紧凑布局下默认折进状态行末尾（「▸伤害记录」），点开后从卡片底部展开成浮层，向下盖住操作栏（不挤压布局），太长在浮层内滚动，再点收起；高度按「卡片底边 → 底栏顶部」的剩余空间由 JS 算。桌面仍然常显。

## 三、引擎怎么跑

**状态**：`{ seed, rng, round, phase, order, queue, turnUid, units[], summons[], summonSeq, log[] }`，每个英雄带 `hp/mp/gauge/charge/cooldowns/breakValue/stunValue/statuses/buffs/mods/effects/scheduled/marks/hpLost`；召唤物是独立单位，带 `side/ownerUid/summonKey/hp/gauge/ttl/effects/statuses/buffs/mods`，不进英雄速度条与行动队列（`gauge` 只给自己的 `attack` 攒条）。

**一次动作**：

```
apply(state, action)
  → 归一化动作（技能蓄力不足会变成 charge）
  → 校验条件（蓝、力、冷却、封锁、一次性、标记门槛）
  → 依次执行 ops（伤害、Buff、持续效果、骰子……）
  → 扣行动；行动用尽则结束角色回合、推进下一个行动者
  → 返回新 state + events + committed
```

**标准回合**：结算持续效果 → 状态/Buff 计时 −1 → 速度条 +速度 → 满 100 就减 100、得 1 个角色回合 → 排行动队列（按速度升序，同速按开局随机顺序，多次行动交错）。

**每步都是纯函数**：`apply` 不改入参；`hash(state)` 是可比较的指纹，回放逐步比对。

## 四、规则口径（改之前先看这张表）

| 项 | 结论 |
|---|---|
| 法伤 | `攻击 ÷ 100 × (100 − 法抗)`，法抗 ≥100 时为 0 |
| 普伤/真伤 | `攻击 − 防御` / 直接等于攻击 |
| 取整 | 伤害与回血结果向 5 的倍数**上**取整；技能文本写明取整方式时以技能为准 |
| 强扣 | 不减免、不加击溃值 |
| 击溃 | 行动，需击溃值 ≥3；状态 `(击溃值−1)×2` 标准回合；**状态中击溃值固定 0** |
| 眩晕 | 只由技能给；防御与法抗视为 0 |
| 蓄蓝/蓄力 | 各消耗 1 行动；力绑定单个技能 |
| 蓄力打断 | 受到非 Buff 伤害清空力；**盾卫与重装例外**（职业特性），「肥肥反弹」蓄力时也不打断 |
| 先手 | 速度低者先，同速开局用种子定 |
| 计时 | 持续效果施加当回合就扣一层（回合结束 −1） |
| 混伤 | 同时造成等量普伤与真伤两段 |
| 标记 | 对手可见、可被对手技能削减或清空 |
| 职业/副业 | 档案写反也能识别（两张表都查）；同名特性取并集，嘲讽相加 |

裁决的完整来龙去脉在 `_local/docs/回合制6.0测试功能-plan.md` 与 `...-角色机制.md`（`_local/` 不推送，随仓库本地保留）。

## 五、技能库

数据都在 `data/skills/`（一个角色一个文件，`index.js` 聚合成下面这个形状）：

```js
{
  version: 1,
  marks: { "王荣逸": [{ key: "shuati", name: "刷题", max: 3, init: 0 }] },
  characters: {
    "刘文哲": [{ id, name, conditionText, cost, charge, cooldown, target, ops, hooks?, requires? }]
  }
}
```

**加一个能上场的角色**：

1. 角色已在档案里（数据库或 `data/seeds/characters.js`），`skills[]` 有名称与条件文本；
2. 在 `data/skills/` 新建该角色的文件（拼音命名，`export default [...]`）并登记进 `index.js` 的 `characters`，每条技能的 `conditionText` **与档案逐字一致**（忽略空白）——不一致会被校验器禁用；
3. 需要计数器就在 `index.js` 的 `marks` 里声明，技能用 `mark` / `markClear` 读写、用 `requires` 卡层数；
4. 跑 `node _local/tools/rpg6-lint.js`（结构：op、字段、mark 引用、锚点），再跑 `node _local/tests/engine/run.mjs`，把新角色补进 `skills.test.mjs` 的 `SHEET` 与 `CHAR`；
5. 在 `_local/docs/回合制6.0测试功能-角色机制.md` 的技能条目旁加 `<!-- skill:角色拼音.技能 -->` 锚点，漏了 lint 会报；
6. 跑 `node _local/tools/rpg6-stats.js --write` 把文档里的角色数 / 技能数写回去，数字不要手改。

**技能字段**：`choices` 三选一（动作带 `choice`）；`input` 输入数值（动作带 `n`）；`costFromLost:{per}` 按累计失血每 per 点降 1 蓝 1 力；`cost.def` 防御代价；`cost.maxMp` 蓝上限代价（机枪射手）；`once` 整局一次；`rollDodge:{sides,values}` 受击掷骰免疫；`buffImmune:[kind]` 随身 Debuff 免疫；`forbidEffect:"key"` 自身有该 key 的持续效果时置灰；`items:[…]` 额外动作（吃碎苹果/功德回血：不消耗行动，`requires` 卡库存，`oncePerRound` 每标准回合限 1 次，`noEffect` 效果在身时不列入口，眩晕/击溃不可用、onlyBasic/noSkill 不拦）；`tick` 可带 `gate`、`period`、`breakOnSourceStatus`、`tag`/`key`、`guard`/`immune`/`breakImmune`/`chargeGuard`（防护层）、`debuff`（负面标记，`dispel scope:"marked"` 清除），`desc` 是 chip 说明。时长单位还有 `enemyRound`（按持有者对手英雄的回合计时，被跳过的回合也算）。
**op 常用项**：`damage`（`type` 支持 `phys/magic/true/last/basic`、`times`、`noBreak`、`addStun`、`fromBuff`、`healBack`、`factor`）、`directLoss`、`heal`、`mp`、`maxHp/maxMp`、`stat`（可带 `restore`、`untilRecast`、`debuff`）、`buff`、`status`（可带 `chargeOk`：noSkill 下仍可蓄力）、`breakValue`、`forceBreak`、`shield`（`hp`/`duration`/`onExpire`）、`tick`、`schedule`、`reflect`、`interrupt`、`dispel`（`scope` 支持 `debuff`/`all`/`status`/`marked`/`breakValue`/`marks`）、`dice`（`times` 连续掷）、`roll`、`strike`（`victim` 指定打谁）、`deny`、`clearMods`（可带 `stats`）、`summon`（`key`）、`setBasicMode`、`if`、`counter`、`mark`（`delta` 支持表达式）、`use`、`note`、`removeEffect`（按 key 移除效果并回滚 `untilRecast` 修正）、`decay`（Buff 逐回合衰减）、`convert`（`beforeDamage` 把受击转为加血上限，强扣不转）。`who` 可以是 `{of:"allEnemies",limit:N}`（群体上限）。
**被动钩子**：`battleStart`（开局一次）、`roundStart`（每标准回合开始）、`basicGate`（普攻门槛）、`basicMod`（多段/无击溃/哑火/倍率）、`basicMode`（普攻改成给召唤物回血）、`basicHit`（普攻命中后）、`beforeDamage`（受击前，可闪避）、`damageDealt` / `damageTaken`（伤害结算后）、`statDrained`（被对手削属性）、`afterAction`（每个动作结束后）。
**数值表达式**：常量、`{stat:"target.def"}`、`{per:…,factor}`、`{hpPercent:"self.lost",percent}`、`{plus:[…]}`、`{minus:[…]}`、`{counter:"…"}`、`{mark:"…"}`、`{summonCount:"key"}`（己方该召唤物存活数量）。
**召唤物口径**：`state.summons` 独立于 `units`，不进英雄速度条、不占行动；只有 `targetable` 且有血的召唤物能被单体选中，无血计时物只显示虚线 chip。召唤物伤害不造成击溃/眩晕，也不触发召唤者的「造成伤害」；群体伤害/群体减益包含召唤物，群体治疗/群体增益只给英雄。单体选目标按敌方战斗单位中的最高嘲讽过滤，`射手` 的 `ignoreTaunt` 例外；召唤物死亡不判负，英雄死亡清空该侧全部召唤物。标准回合末按 `aura → attack → 到期 onExpire → ttl-1` 结算；带 `attack` 的召唤物按自身速度攒行动条（满 100 出手一次，速度 10 = 每 10 标准回合一次），攒满那一拍被眩晕/击溃则作废，`breakImmune` 的召唤物无法被击溃。

## 六、数据与后端

表 `rpg_battles`（迁移脚本 `_local/sql/rpg-battle-setup.sql`）：

| 列 | 说明 |
|---|---|
| `id` | 客户端生成，`b` + 时间戳 + 随机 |
| `seed` | **原始种子**（不是随机数状态） |
| `character_a/b`、`name_a/b` | 双方角色 id 与名字（不存快照） |
| `actions` | 归一化动作数组，回放的唯一依据 |
| `result`、`steps`、`rounds` | 结局与规模 |
| `final_hash` | 战后状态指纹，回放用来判断是否与当前角色数据一致 |
| `engine_version` | 规则版本；不一致时页面标「旧引擎战报」 |

权限：匿名 **只读 + 只插**，没有 update/delete（PATCH/DELETE 返回 `401 42501`）。写错的战报只能 service_role 手工删。

保留期 30 天：`rpc/rpg_battles_purge`（`security definer`，期限写死在函数里，不接收参数）删 `created_at < now() - interval '30 days'` 的行。`battles.html` 每次加载调一次，删到东西才重查列表。迁移脚本 `_local/sql/rpg-battle-retention.sql`。

数据层函数在 `js/rpg-data.js`：`listBattles`（可带 `character` 只查某一方的对局）/ `getBattle` / `createBattle` / `purgeBattles`，与角色读写共用同一套 `get` / `send`（缺列会自动降级重试）。

```powershell
& $node _local/tests/engine/batch.mjs --seeds=4     # 23 人两两配对压测，2116 局
& $node _local/tests/run-all.mjs --group=回合制      # 浏览器用例，12 条（不需要令牌，含一条 844×390 横屏带召唤物断言）
& $node _local/tools/rpg6-lint.js                   # 技能库结构校验：op 字段、mark 声明、锚点、版本号
& $node _local/tools/rpg6-stats.js --check          # 文档里的角色数/技能数/op 数是否与数据一致
& $node _local/pw/rpg-live-check.mjs                # 线上验收：项目页 → 完整一局 → 回放 → 列表
& powershell -NoProfile -ExecutionPolicy Bypass -File tools\check.ps1
```

`rpg6-lint` 与 `rpg6-stats --check` 都挂在 `check.ps1` 里，所以只在本地改文档时单独跑；`--write` 能把文档里的数字写回去（不要手改，会被下一次 `--check` 抓住）。

压测会校验血量/蓝/上限/击溃值/残留状态/标记/重放指纹，结果写到 `_local/tests/reports/`。本地预览需要静态服务器：`python -m http.server 9300 --bind 127.0.0.1`，访问 `http://127.0.0.1:9300/rpg6.0/test.html`。
