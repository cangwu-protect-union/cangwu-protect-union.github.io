## 一、玩家视角

1. 选两名角色，填种子（留空则随机）。**速度低者先手**，同速在开局用种子随机决定。
2. 每个标准回合，角色速度条 +速度；累计满 100 就获得一次角色回合，每回合 1 点行动（爆发者 2 点）。
3. 行动可选：普攻、击溃、蓄蓝、释放技能。**蓄力**不是按钮——点一个蓄力不足的技能就是给它蓄力 1 点，消耗 1 行动。
   少数技能释放时要输入一个数值：田誉清的「霰弹枪」会弹出一个输入框，填要支付的蓝（1..当前蓝），确认后才结算。
4. 击溃：目标击溃值 ≥3 才可用，进入击溃后无法行动；**击溃期间击溃值固定为 0**，击溃结束从 0 重新累计。
5. 蓄蓝 +1 蓝；蓝与力都用于技能。力绑定单个技能，换技能蓄力会清零。
6. 打完弹出结果，战报自动入库；`?record=<id>` 可逐步回放，也能从任意一步「接着打」。中途刷新会提示「继续上一局」。

界面五块：左侧速度条预期（21 行，可折叠）、两块角色状态（状态带 + 可展开的伤害记录）、右上 Buff 详情（悬停图标）、下方两个角色查询框（技能与基础操作）、底部战斗日志（桌面常显，手机折成一行）。有召唤物时，角色卡底部多一条召唤物带：有血的显示血量与剩余回合、可被单体选中，无血的用虚线只显示剩余回合；选择目标时可选召唤物会高亮，被嘲讽保护的目标会提示。

**手机**：竖屏会被「请横屏」遮罩挡住，唯一入口是「横屏继续」——它请求全屏并尝试 `screen.orientation.lock("landscape")`；浏览器不支持锁方向（iOS 网页）时就只提示手动横过来。遮罩由 JS 判定（粗指针 + 有触摸 + 视口短边 ≤520）后才显示，桌面窄窗口、平板、鼠标设备都不弹。横屏下换成紧凑布局：站点导航隐藏、速度条收成一行、双方状态与技能左右并排、页面本身不滚（各列内部滚动）、技能效果默认收起（点行尾「效果」展开）、Buff 改为点图标弹气泡（手机没有 hover）。召唤物带在紧凑布局下横向滚动，不额外占高度；844×390 带墓的用例已断言一屏。

**折叠面板**：桌面只有速度条预期可折（同原来，展开只在原位铺开）；手机横屏下速度条预期与战斗日志都默认只占一行，展开后铺满视口、盖住其它所有内容（`position: fixed; inset: 0`，标题行 sticky 当关闭入口），长内容在面板内滚动。桌面战斗日志仍是常显的普通区块，不折叠、不变浮层。

**伤害记录**：紧凑布局下每个角色卡的伤害记录默认折进状态行末尾（「▸伤害记录」），点开后从卡片底部展开成浮层，向下盖住操作栏（不挤压布局），太长在浮层内滚动，再点一次收起；高度按「卡片底边 → 底栏顶部」的剩余空间由 JS 算。桌面仍然在卡片内常显。

## 三、引擎怎么跑

**状态**：`{ seed, rng, round, phase, order, queue, turnUid, units[], summons[], summonSeq, log[] }`，每个英雄带 `hp/mp/gauge/charge/cooldowns/breakValue/stunValue/statuses/buffs/mods/effects/scheduled/marks/hpLost`；召唤物是独立单位，带 `side/ownerUid/summonKey/hp/ttl/effects/statuses/buffs/mods`，不进速度条。

**一次动作**：

```
apply(state, action)
  → 归一化动作（技能蓄力不足会变成 charge）
  → 校验条件（蓝、力、冷却、封锁、一次性、标记门槛）
  → 依次执行 ops（伤害、Buff、持续效果、骰子……）
  → 扣行动；行动用尽则结束角色回合、推进下一个行动者
  → 返回新 state + events + committed
```

**标准回合**：结算持续效果 → 状态/Buff 计时 −1 → 速度条 +速度 → 满 100 就减 100、得 1 个角色回合 → 排行动队列（按速度升序，同速按开局随机顺序，多次行动交错）。

**每步都是纯函数**：`apply` 不改入参；`hash(state)` 是可比较的指纹，回放逐步比对。

## 四、规则口径（改之前先看这张表）

| 项 | 结论 |
|---|---|
| 法伤 | `攻击 ÷ 100 × (100 − 法抗)`，法抗 ≥100 时为 0 |
| 普伤/真伤 | `攻击 − 防御` / 直接等于攻击 |
| 取整 | 伤害与回血结果向 5 的倍数**上**取整；技能文本写明取整方式时以技能为准 |
| 强扣 | 不减免、不加击溃值 |
| 击溃 | 行动，需击溃值 ≥3；状态 `(击溃值−1)×2` 标准回合；**状态中击溃值固定 0** |
| 眩晕 | 只由技能给；防御与法抗视为 0 |
| 蓄蓝/蓄力 | 各消耗 1 行动；力绑定单个技能 |
| 蓄力打断 | 受到非 Buff 伤害清空力；**盾卫与重装例外**（职业特性），「肥肥反弹」蓄力时也不打断 |
| 先手 | 速度低者先，同速开局用种子定 |
| 计时 | 持续效果施加当回合就扣一层（回合结束 −1） |
| 混伤 | 同时造成等量普伤与真伤两段 |
| 标记 | 对手可见、可被对手技能削减或清空 |
| 职业/副业 | 档案写反也能识别（两张表都查）；同名特性取并集，嘲讽相加 |

裁决的完整来龙去脉在 `_local/docs/回合制6.0测试功能-plan.md` 与 `...-角色机制.md`（`_local/` 不推送，随仓库本地保留）。

## 五、技能库

数据都在 `data/battle-skills.js`：

```js
window.RPG6_SKILLS = {
  version: 1,
  marks: { "王荣逸": [{ key: "shuati", name: "刷题", max: 3, init: 0 }] },
  characters: {
    "刘文哲": [{ id, name, conditionText, cost, charge, cooldown, target, ops, hooks?, requires? }]
  }
};
```

**加一个能上场的角色**：

1. 角色已在档案里（数据库或 `characters.js`），`skills[]` 有名称与条件文本；
2. 在 `characters` 里加一个角色块，每条技能的 `conditionText` **与档案逐字一致**（忽略空白）——不一致会被校验器禁用；
3. 需要计数器就在 `marks` 里声明，技能用 `mark` / `markClear` 读写、用 `requires` 卡层数；
4. 跑 `node _local/tests/engine/run.mjs`，再把新角色补进 `skills.test.mjs` 的 `SHEET` 与 `CHAR`。

**技能字段**：`choices` 是释放时三选一（动作带 `choice`，选中哪项只跑哪项的 `ops`；旧战报没有 `choice` 时退回 `ops` 整套）；`input` 是释放时输入一个数值（动作带 `n`，用于田誉清「霰弹枪」的支付蓝）；`costFromLost:{per}` 按累计失血每 per 点降 1 蓝 1 力（羊书含「杨舒涵之墓」，最低 0）；`once` 整局只能释放一次；`rollDodge:{sides,values}` 是受击掷骰免疫（宋知远「皮糙肉厚」：每次伤害结算前先掷 d6，掷出 1/3/5 该次伤害整体不结算）；`buffImmune:[kind]` 是随身 Debuff 免疫（加 Buff 时拦截、标准回合开始再清一次兜底）；`tick` 可带 `gate:{sides,cancel}`（持有者行动前掷骰跳过行动）、`period`（每 period 个标准回合结算一次）与 `breakOnSourceStatus`（来源被击晕/击溃即结束，用于张克太「吉罢之歌」），`desc` 用作出现在 chip 上的说明。
**op 常用项**：`damage`（`type` 支持 `phys/magic/true/last/basic`、`times`、`noBreak`、`noStun`、`fromBuff`、`healBack`、`factor`）、`directLoss`、`heal`、`mp`、`maxHp/maxMp`、`stat`、`buff`、`status`、`breakValue`、`forceBreak`、`tick`、`schedule`、`reflect`、`interrupt`、`dispel`（含 `scope:"marks"`）、`dice`（`times` 连续掷）、`roll`（掷骰存进 counter）、`strike`（立即执行一次普攻）、`deny`（否决普攻）、`clearMods`（可带 `stats` 只清指定属性）、`summon`（`key` 指向 `summons` 定义）、`setBasicMode`、`if`、`counter`、`mark`、`use`、`note`。
**被动钩子**：`battleStart`（开局一次）、`roundStart`（每个标准回合开始，用于宋知远「皮糙肉厚」的回血）、`basicGate`（普攻门槛）、`basicMod`（多段/无击溃/哑火/倍率）、`basicMode`（把普攻改成给召唤物回血）、`basicHit`（普攻命中后）、`beforeDamage`（受击前，可闪避）、`damageDealt` / `damageTaken`（伤害结算后）、`statDrained`（被对手削属性）、`afterAction`（每个动作结束后，用于刘滨路「动能」）。
**数值表达式**：常量、`{stat:"target.def"}`、`{per:…,factor}`、`{hpPercent:"self.lost",percent}`、`{plus:[…]}`、`{minus:[…]}`、`{counter:"…"}`、`{mark:"…"}`。
**召唤物口径**：`state.summons` 独立于 `units`，不进速度条、不占行动；只有 `targetable` 且有血的召唤物能被单体选中，无血计时物只显示虚线 chip。召唤物伤害不造成击溃/眩晕，也不触发召唤者的「造成伤害」；群体伤害/群体减益包含召唤物，群体治疗/群体增益只给英雄。单体选目标时按敌方战斗单位中的最高嘲讽过滤，`射手` 的 `ignoreTaunt` 例外；召唤物死亡不判负，英雄死亡清空该侧全部召唤物。召唤物在标准回合末按 `aura → attack → 到期 onExpire → ttl-1` 结算，被眩晕时跳过 `attack`，`breakImmune` 的召唤物无法被击溃。

**现有 19 人 67 条技能**，其中 2 条标了 `unsupported`（界面置灰并显示原因）：

| 角色 · 技能 | 原因 |
|---|---|
| 张家铭 · 卫委壮观 | 花防御/法抗主动闪避需要「可选防御动作」，界面没有入口 |
| 王荣逸 · 学习氛围 | 「可停止」需要关闭已挂持续效果的入口 |

金圣杰「光」按原文实现（6 蓝、三段各 9995），但蓝上限只有 5，所以永远放不出来，不算 `unsupported`。

## 六、数据与后端

表 `rpg_battles`（迁移脚本 `_local/sql/rpg-battle-setup.sql`）：

| 列 | 说明 |
|---|---|
| `id` | 客户端生成，`b` + 时间戳 + 随机 |
| `seed` | **原始种子**（不是随机数状态） |
| `character_a/b`、`name_a/b` | 双方角色 id 与名字（不存快照） |
| `actions` | 归一化动作数组，回放的唯一依据 |
| `result`、`steps`、`rounds` | 结局与规模 |
| `final_hash` | 战后状态指纹，回放用来判断是否与当前角色数据一致 |
| `engine_version` | 规则版本；不一致时页面标「旧引擎战报」 |

权限：匿名 **只读 + 只插**，没有 update/delete（PATCH/DELETE 返回 `401 42501`）。写错的战报只能 service_role 手工删。

保留期 30 天：`rpc/rpg_battles_purge`（`security definer`，期限写死在函数里，不接收参数）删 `created_at < now() - interval '30 days'` 的行。`battles.html` 每次加载调一次，删到东西才重查列表。迁移脚本 `_local/sql/rpg-battle-retention.sql`。

数据层函数在 `js/rpg-data.js`：`listBattles`（可带 `character` 只查某一方的对局）/ `getBattle` / `createBattle` / `purgeBattles`，与角色读写共用同一套 `get` / `send`（缺列会自动降级重试）。

## 十、坑（都真实踩过）

1. `state.seed` 必须是**原始种子**；存混淆后的 rng 值会让回放从第一步发散。
2. 战报存 `committed` 动作；点技能蓄力不足时动作会被归一化成 `charge`。
3. `set` 不会清掉已有的 `add`，要做上限就加「差值」。
4. 回合制效果的 `unit` 是 `selfRound` / `targetRound`，不是 `"turn"`。
5. 状态/Buff 事件要带 `label`，否则界面显示内部 kind（如 `noDeath`）。
6. 标记必须先声明，没声明时 op 静默返回。
7. 技能条件与档案不一致会被禁用——这是校验，不是 bug。
8. 改规则要同时升 `data/config.js` 的 `engineVersion`，旧战报才会被标成旧引擎。
9. `docgen` 只扫模块根下的 `js/*.js`，`js/engine`、`js/battle` 不进架构图，说明写在 `架构.md` 手写区。
10. 技能禁用时只有「不是他的回合」才拦截点击；条件不满足（缺蓝、层数不够）要放行点击并给出原因。
11. 紧凑布局的断点必须写 `(orientation: landscape) and (max-height: 520px)`。只写 `max-width: 900px` 会把 844×390 的手机横屏也当成单列竖排——这是老版在手机上要滑三屏的原因。
12. 遮罩的显示条件不只看 CSS：JS 判 `(pointer: coarse)` + `maxTouchPoints > 0` + 视口短边 ≤520，命中才给 `<html>` 加 `is-phone`，CSS 只在 `is-phone` + 竖屏时显示遮罩。只写媒体的 `(pointer: coarse)` 会把触屏笔记本、平板也算进来。测遮罩要经 CDP `Emulation.setDeviceMetricsOverride({mobile:true})` + `setTouchEmulationEnabled`，`setViewportSize` 不改 pointer 与触摸点数。
13. 紧凑布局下 `.bq-skills` 自己滚、`.bq-actions` 固定在卡片底部；否则展开技能效果会把「普攻/击溃/蓄蓝」顶出可见区。
14. 伤害记录浮层用绝对定位，靠 `.battle-unit { overflow: visible }` 才能盖出卡片；改回 `auto` 会被裁掉。高度由 `applyLogPanel()` 现算：`max-height` 取「卡片底边 → 底栏顶边」，`min-height` 至少盖到技能卡底边，否则半行技能文字会露在浮层下面。不要写死 `vh`。
15. 折叠面板用原生 `<details>`，`open` 状态存在 `speedOpen` / `battleLogOpen` 里，每次 `render()` 重建 DOM 后按它恢复；直接读 DOM 会在下一次 render 丢状态。战斗日志由 `renderBattleLog(state, open, collapsible)` 决定输出：`collapsible` 为假时渲染成 `<section>`（桌面常显），为真才输出 `<details>`。
16. 测浮层的用例不能先注入行再点开：点开会触发 `render()` 重建 DOM，注入的内容会被冲掉，必须先点开再塞行。
17. 手机横屏的展开态统一用 `position: fixed; inset: 0` 铺满视口；面板里的 `<summary>` 要 `position: sticky` 顶住，否则长日志滚下去就没有关闭入口了。这些规则只写在紧凑断点里，别提到全局——桌面一旦被卷进去，战斗日志会变成盖住整页的浮层。
18. 受击掷骰免疫不能写成 `beforeDamage` 钩子：那条路径在 `noReaction`（江雨轩「肥肥反弹」的反弹伤害、被动强制普攻）时会跳过，毛毛就挡不住这些伤害。它走 `damage.hit` 最前面的 `skills.rollDodge`，与钩子无关；`buffImmune` 同理走 `skills.immuneBuffs`，在 `addBuff` 里拦截。
