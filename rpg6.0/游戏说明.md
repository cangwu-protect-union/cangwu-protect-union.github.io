## 一、玩家视角

1. 选两名角色，填种子（留空则随机）。**速度低者先手**，同速在开局用种子随机决定。
2. 每个标准回合，角色速度条 +速度；累计满 100 就获得一次角色回合，每回合 1 点行动（爆发者 2 点）。
3. 行动可选：普攻、击溃、蓄蓝、释放技能。**蓄力**不是按钮——点一个蓄力不足的技能就是给它蓄力 1 点，消耗 1 行动。
4. 击溃：目标击溃值 ≥3 才可用，进入击溃后无法行动；**击溃期间击溃值固定为 0**，击溃结束从 0 重新累计。
5. 蓄蓝 +1 蓝；蓝与力都用于技能。力绑定单个技能，换技能蓄力会清零。
6. 打完弹出结果，战报自动入库；`?record=<id>` 可逐步回放，也能从任意一步「接着打」。中途刷新会提示「继续上一局」。

界面五块：左侧速度条预期（21 行，可折叠）、两块角色状态（状态带 + 可展开的伤害记录）、右上 Buff 详情（悬停图标）、下方两个角色查询框（技能与基础操作）、底部战斗日志（可折叠）。

**手机**：竖屏会被「请横屏」遮罩挡住，唯一入口是「横屏继续」——它请求全屏并尝试 `screen.orientation.lock("landscape")`；浏览器不支持锁方向（iOS 网页）时就只提示手动横过来。横屏下换成紧凑布局：站点导航隐藏、速度条收成一行、双方状态与技能左右并排、页面本身不滚（各列内部滚动）、技能效果默认收起（点行尾「效果」展开）、Buff 改为点图标弹气泡（手机没有 hover）、战斗日志收成一行摘要。

**伤害记录**：紧凑布局下每个角色卡的伤害记录默认折进状态行末尾（「▸伤害记录」），点开后从卡片底部展开成浮层，向下盖住操作栏（不挤压布局），太长在浮层内滚动，再点一次收起；高度按「卡片底边 → 底栏顶部」的剩余空间由 JS 算。桌面仍然在卡片内常显。

## 三、引擎怎么跑

**状态**：`{ seed, rng, round, phase, order, queue, turnUid, units[], log[] }`，每个单位带 `hp/mp/gauge/charge/cooldowns/breakValue/stunValue/statuses/buffs/mods/effects/scheduled/marks`。

**一次动作**：

```
apply(state, action)
  → 归一化动作（技能蓄力不足会变成 charge）
  → 校验条件（蓝、力、冷却、封锁、一次性、标记门槛）
  → 依次执行 ops（伤害、Buff、持续效果、骰子……）
  → 扣行动；行动用尽则结束角色回合、推进下一个行动者
  → 返回新 state + events + committed
```

**标准回合**：结算持续效果 → 状态/Buff 计时 −1 → 速度条 +速度 → 满 100 就减 100、得 1 个角色回合 → 排行动队列（按速度升序，同速按开局随机顺序，多次行动交错）。

**每步都是纯函数**：`apply` 不改入参；`hash(state)` 是可比较的指纹，回放逐步比对。

## 四、规则口径（改之前先看这张表）

| 项 | 结论 |
|---|---|
| 法伤 | `攻击 ÷ 100 × (100 − 法抗)`，法抗 ≥100 时为 0 |
| 普伤/真伤 | `攻击 − 防御` / 直接等于攻击 |
| 取整 | 伤害与回血结果向 5 的倍数**上**取整；技能文本写明取整方式时以技能为准 |
| 强扣 | 不减免、不加击溃值 |
| 击溃 | 行动，需击溃值 ≥3；状态 `(击溃值−1)×2` 标准回合；**状态中击溃值固定 0** |
| 眩晕 | 只由技能给；防御与法抗视为 0 |
| 蓄蓝/蓄力 | 各消耗 1 行动；力绑定单个技能 |
| 先手 | 速度低者先，同速开局用种子定 |
| 计时 | 持续效果施加当回合就扣一层（回合结束 −1） |
| 混伤 | 同时造成等量普伤与真伤两段 |
| 标记 | 对手可见、可被对手技能削减或清空 |
| 职业/副业 | 档案写反也能识别（两张表都查）；同名特性取并集，嘲讽相加 |

裁决的完整来龙去脉在 `_local/docs/回合制6.0测试功能-plan.md` 与 `...-角色机制.md`（`_local/` 不推送，随仓库本地保留）。

## 五、技能库

数据都在 `data/battle-skills.js`：

```js
window.RPG6_SKILLS = {
  version: 1,
  marks: { "王荣逸": [{ key: "shuati", name: "刷题", max: 3, init: 0 }] },
  characters: {
    "刘文哲": [{ id, name, conditionText, cost, charge, cooldown, target, ops, hooks?, requires? }]
  }
};
```

**加一个能上场的角色**：

1. 角色已在档案里（数据库或 `characters.js`），`skills[]` 有名称与条件文本；
2. 在 `characters` 里加一个角色块，每条技能的 `conditionText` **与档案逐字一致**（忽略空白）——不一致会被校验器禁用；
3. 需要计数器就在 `marks` 里声明，技能用 `mark` / `markClear` 读写、用 `requires` 卡层数；
4. 跑 `node _local/tests/engine/run.mjs`，再把新角色补进 `skills.test.mjs` 的 `SHEET` 与 `CHAR`。

**技能字段**：`choices` 是释放时三选一（动作带 `choice`，选中哪项只跑哪项的 `ops`；旧战报没有 `choice` 时退回 `ops` 整套）；`tick` 可带 `gate:{sides,cancel}`，持有者每次行动前掷骰，掷出 `cancel` 里的点数就跳过这次行动，`desc` 用作出现在 chip 上的说明。
**op 常用项**：`damage`（`type` 支持 `phys/magic/true/last/basic`、`times`、`noBreak`、`fromBuff`、`healBack`、`factor`）、`directLoss`、`heal`、`mp`、`maxHp/maxMp`、`stat`、`buff`、`status`、`breakValue`、`forceBreak`、`tick`、`schedule`、`reflect`、`interrupt`、`dispel`（含 `scope:"marks"`）、`dice`、`if`、`counter`、`mark`、`use`、`note`。
**数值表达式**：常量、`{stat:"target.def"}`、`{per:…,factor}`、`{hpPercent:"self.lost",percent}`、`{plus:[…]}`、`{minus:[…]}`、`{counter:"…"}`、`{mark:"…"}`。

**现有 12 人 41 条技能**，其中 3 条标了 `unsupported`（界面置灰并显示原因）：

| 角色 · 技能 | 原因 |
|---|---|
| 宋知远 · 皮糙肉厚 | 受击免疫要在伤害结算前拦截，尚无该钩子 |
| 张家铭 · 卫委壮观 | 花防御/法抗主动闪避需要「可选防御动作」，界面没有入口 |
| 王荣逸 · 学习氛围 | 「可停止」需要关闭已挂持续效果的入口 |

## 六、数据与后端

表 `rpg_battles`（迁移脚本 `_local/sql/rpg-battle-setup.sql`）：

| 列 | 说明 |
|---|---|
| `id` | 客户端生成，`b` + 时间戳 + 随机 |
| `seed` | **原始种子**（不是随机数状态） |
| `character_a/b`、`name_a/b` | 双方角色 id 与名字（不存快照） |
| `actions` | 归一化动作数组，回放的唯一依据 |
| `result`、`steps`、`rounds` | 结局与规模 |
| `final_hash` | 战后状态指纹，回放用来判断是否与当前角色数据一致 |
| `engine_version` | 规则版本；不一致时页面标「旧引擎战报」 |

权限：匿名 **只读 + 只插**，没有 update/delete（PATCH/DELETE 返回 `401 42501`）。写错的战报只能 service_role 手工删。

数据层函数在 `js/rpg-data.js`：`listBattles` / `getBattle` / `createBattle`，与角色读写共用同一套 `get` / `send`（缺列会自动降级重试）。

## 十、坑（都真实踩过）

1. `state.seed` 必须是**原始种子**；存混淆后的 rng 值会让回放从第一步发散。
2. 战报存 `committed` 动作；点技能蓄力不足时动作会被归一化成 `charge`。
3. `set` 不会清掉已有的 `add`，要做上限就加「差值」。
4. 回合制效果的 `unit` 是 `selfRound` / `targetRound`，不是 `"turn"`。
5. 状态/Buff 事件要带 `label`，否则界面显示内部 kind（如 `noDeath`）。
6. 标记必须先声明，没声明时 op 静默返回。
7. 技能条件与档案不一致会被禁用——这是校验，不是 bug。
8. 改规则要同时升 `data/config.js` 的 `engineVersion`，旧战报才会被标成旧引擎。
9. `docgen` 只扫模块根下的 `js/*.js`，`js/engine`、`js/battle` 不进架构图，说明写在 `架构.md` 手写区。
10. 技能禁用时只有「不是他的回合」才拦截点击；条件不满足（缺蓝、层数不够）要放行点击并给出原因。
11. 紧凑布局的断点必须写 `(orientation: landscape) and (max-height: 520px)`。只写 `max-width: 900px` 会把 844×390 的手机横屏也当成单列竖排——这是老版在手机上要滑三屏的原因。
12. 遮罩的显示条件用 `(pointer: coarse)` 排除窄窗口的桌面浏览器；Playwright 默认不改 pointer，测遮罩要经 CDP `Emulation.setDeviceMetricsOverride({mobile:true})`，`setViewportSize` 不够。
13. 紧凑布局下 `.bq-skills` 自己滚、`.bq-actions` 固定在卡片底部；否则展开技能效果会把「普攻/击溃/蓄蓝」顶出可见区。
14. 伤害记录浮层用绝对定位，靠 `.battle-unit { overflow: visible }` 才能盖出卡片；改回 `auto` 会被裁掉。浮层高度由 `applyLogPanel()` 按「卡片底边 → 底栏顶边」现算，不能写死 `vh`，底栏高度随设备变。
15. 折叠面板（速度条、战斗日志）用原生 `<details>`，`open` 状态存在 `speedOpen` / `battleLogOpen` 里，每次 `render()` 重建 DOM 后按它恢复；直接读 DOM 会在下一次 render 丢状态。
16. 测浮层的用例不能先注入行再点开：点开会触发 `render()` 重建 DOM，注入的内容会被冲掉，必须先点开再塞行。
