# 策略实验室 · 实现方案

状态：设计稿，未开工。本文档给实现者看；使用方式见 [使用说明.md](使用说明.md)。

## 0. 一句话

给 N 个角色，每个角色为每个对手练出 3 套打分式打法，两两组合跑出胜率矩阵，再从矩阵上精确判定每对角色属于静止、封闭还是开放。

## 1. 实测基线（本机，2026-11-15）

| 指标 | 值 | 怎么量的 |
|---|---|---|
| 分析吞吐 | 339 局/秒/核 | 57 局，清空日志、不跑不变量、不跑重放 |
| 校验吞吐 | 25 局/秒/核 | `batch.mjs --pairs=smoke --seeds=1`（含每步不变量 + 每局重放） |
| 单局耗时 | p50 1.56ms / p90 4.26ms / max 25ms | 同上，长局 244 步 |
| 单局步数 | 平均 36 / 最长 244 | 同上 |
| 每决策候选动作 | 平均 4.04 / p90 5 / 最多 8 | 同上 |
| 角色 / 技能 | 19 / 67，引擎 `6.0-engine.7` | `rpg6.0/data/battle-skills.js`、`rpg6.0/data/config.js:8` |
| 逻辑核数 | 12 | `$env:NUMBER_OF_PROCESSORS` |

三条直接影响的结论：

1. **成本不是问题。** 之前按 25 局/秒估的成本高估了 13 倍。5 角色全流程（训练 + 矩阵）在 12 核上约 10 分钟，19 角色约 2 小时。
2. **打分函数只在 4 个选项里排序。** 每决策平均 4 个合法动作、最多 8 个。特征不用做得精细，权重也不用多。
3. **清日志安全且必要。** `state.hash`（`rpg6.0/js/engine/state.js:361`）不含 `log`，每步 `state.log.length = 0` 不影响判定、不影响重放，实测提速约 2 倍。

## 2. 目标与非目标

目标：

- 在本地直接调用引擎，不经页面、不经数据库。
- 每对角色得到一张胜率矩阵，并只从矩阵上判定静止 / 封闭 / 开放。
- 每个角色对每个对手的打法能翻译成人能读的规则句子。
- 结论带证据：样本量、置信区间、稳定性复核。

非目标：

- 不做自动改数值的平衡器。
- 不做页面、不做可视化（P4 之前）。
- 不追求策略空间的全局最优，只要求"证据覆盖到的范围内结论正确"。

## 3. 两条链路，不要混

| 链路 | 干什么 | 有误差吗 |
|---|---|---|
| A 训练 | 搜出 3 套好打法 | 有。启发式搜索，可能局部最优 |
| B 判定 | 从最终矩阵算状态 | 无。矩阵给定后是精确计算 |

误差只在"打法覆盖得够不够"，不在"状态算得对不对"。报告里要把这句话写进去。

## 5. 引擎接入

照 `_local/tests/engine/batch.mjs` 的方式，在 Node 里按序 require 引擎文件，再 require 技能库。第一个必须是 `version.js`（它设置 `B.ENGINE_VERSION`，标定表用它做版本校验）：

```
version → rng → rules → traits → state → damage → effect-ops → timeline
→ conditions → skills → summons → actions → battle
```

然后 `B.skills.load(globalThis.RPG6_SKILLS)`。

角色档案用 `vm` 在沙箱里读 `rpg6.0/data/characters.js`，取 `window.RPG_SEED_CHARACTERS`，再按技能库里的角色名过滤。

**不要**改引擎的加载顺序或模块路径，`battle.mjs` 依赖 `root.RPG6B` 这个全局。

## 6. 动作枚举器

`batch.mjs:74` 的 `candidates()` 是雏形，直接搬过来有三处要改：

| 问题 | 现状 | 改成 |
|---|---|---|
| `skill.input` 只取 min 与 max 两档 | 数值档位可能 1–20 | 取 min、min+1、mid、max 最多 4 档 |
| 目标只有敌方英雄 | 有血召唤物也该进候选 | 用 `state.combatantsOf` + `maxTauntUids` 过滤，与 `battle.available` 同口径 |
| 不校验嘲讽 | 选中被嘲讽保护的目标会抛错 | 单体目标走 `skills.maxTauntUids` |

自检（P0 验收）：随机取 200 个决策点，枚举出的每个动作都在克隆状态上真实 `apply` 一次，成功率必须 100%。任何抛错都要在训练前修掉，不能留到跑批阶段当成"引擎异常"。

## 7. 技能标定表

打分需要"这个动作能打多少伤害"，但不能复制引擎的伤害公式（会与引擎发散）。做法是**用引擎给引擎打表**：

1. 造一个固定假人对局：攻击方面板固定（atk 100，技能按角色原值），受击方 def 0、mres 0、hp 100000。
2. 对每条技能强制释放一次，读受击方血量差，得到基准伤害与段数。
3. 治疗的技能同法读回血量。
4. 结果写入 `data/calibration.json`，形如 `{ "liuwenzhe.xxx": { damage: 180, hits: 1, type: "phys", heal: 0 } }`。

运行时的伤害估计（**三种类型公式不同，不能统一按比例缩放**）：

| 类型 | 引擎公式 | 标定值含义 | 运行时 |
|---|---|---|---|
| 普伤 `phys` | `max(0, 攻击 − 防御)` | 假人 def=0，标定值就是攻击 | `max(0, 标定值 − 目标防御)` |
| 法伤 `magic` | `攻击 ÷ 100 × (100 − 法抗)` | 假人 mres=0，标定值就是攻击 | `标定值 ÷ 100 × (100 − 目标法抗)` |
| 真伤 `true` | `攻击` | 标定值就是伤害 | 不修正 |

`last`（按已损血算）与 `basic`（按面板算）是动态伤害，标定值只作参考，按真伤处理。

另外两类要特别标注：

- `delayed`：`tick` / `schedule` 这类延迟伤害，标定时当场伤害为 0，只记 `delayed: true`，打分时按"资源收益"处理，不按伤害处理。
- `mixed`：一条技能里同时有多个伤害类型（如庄文希的普伤+真伤），标定值是多段之和，无法拆开，按真伤估。

**注意**：`B.effectOps.valueOf` 实测是坏的——它等于 `Object.prototype.valueOf`（`effect-ops.js` 里 `api.valueOf = valueOf` 引用了未定义的 `valueOf`），调用后返回 `effectOps` 这个对象而不是数值。标定不要依赖它。若要走数值求值路线，需要在 `effect-ops.js` 补一个 `api.evalValue = evalValue` 的只读导出，按项目规矩这要升 `engineVersion` 并同步文档。**优先走标定表路线，不动引擎。**

## 8. 打分策略

### 8.1 特征

全部归一到 0–1，尺度不统一权重就没意义。

| 符号 | 含义 | 来源 | 归一化 |
|---|---|---|---|
| `d` | 预计伤害 | 标定表 × 抗性修正 | ÷ 对手当前血，超过 1 记 1 |
| `k` | 能否一击致死 | `d ≥ 1` | 0 或 1 |
| `h` | 预计回血 | 标定表 | ÷ 自己血上限，超过 1 记 1 |
| `g` | 后续资源收益 | 蓄蓝 / 蓄力进度 / 增益层数 | ÷ 该资源上限 |
| `c` | 消耗 | 蓝耗 ÷ 蓝上限 + 蓄力占格 × 0.3 | 夹到 0–1 |
| `x` | 副作用 | 给对面积累击溃值、浪费关键技能、打在免疫单位上 | 0–1，需手标或规则判断 |

### 8.2 打分

```
score = w[t][0]·d + w[t][1]·k + w[t][2]·h + w[t][3]·g − w[t][4]·c − w[t][5]·x
```

`t` 是自身血量档位：≥60% 记 0，30%–60% 记 1，<30% 记 2。每档 6 个权重，共 18 个参数，各在 0–1。

分档是 P1 增强加的：单档权重只能表达"偏好"，表达不了"血少了就换打法"。特征是线性的，没有分档时很多对局的矩阵极差为 0（换权重选的是同一批动作）。

第 6 个特征 `x` 定义为"空转"：预计伤害低于对手当前血 5%、又不回血、又不攒资源，记 1。用来处罚浪费行动。

### 8.3 三条硬规则（不参与打分）

1. 非法动作已由枚举器剔除。
2. 全部同分时，用种子驱动的随机数挑一个（可复现，不会死循环）。
3. 能一击致死时直接选，不再打分。

### 8.4 策略的数据形状

```json
{
  "id": "王荣逸.vs.李硕.0",
  "w": [0.62, 0.91, 0.35, 0.20, 0.48, 0.10, 0.55, 0.72, 0.83, 0.12, 0.31, 0.44, 0.90, 0.47, 0.66, 0.22, 0.15, 0.58],
  "obj": 0.66,
  "min": 0.52,
  "signature": "9f2c1a…",
  "readable": ["血量≥60%：伤害优先", "血量30%–60%：回血优先", "血量<30%：补刀优先"]
}
```

`w` 是 18 个数：三档 × 六个特征。

`signature` 是行为签名：用 8 个固定种子、2 个探针对手跑一遍，把动作序列拼起来取哈希。两套参数不同但签名相同的策略视为重复，只留一套。这一步不能省，否则矩阵里会有大量重复列，平坦度和环检测全被污染。

## 9. 单局执行

```js
function play(A, B, policyA, policyB, seed, cap = 400) {
  let state = RPG6B.battle.create({ seed, a: A, b: B }).state;
  let steps = 0;
  while (state.phase !== "finished" && steps < cap) {
    const list = enumerate(state);
    const side  = state.turnUid === state.units[0].uid ? "a" : "b";
    const pick  = choose(state, list, side === "a" ? policyA : policyB);
    state = RPG6B.battle.apply(state, pick).state;
    state.log.length = 0;
    steps += 1;
  }
  return {
    result: state.phase === "finished" ? state.result : "draw",
    stalled: state.phase !== "finished",
    steps,
    rounds: state.round
  };
}
```

要点：

- `cap` 默认 400（实测最长 244 步）。超限记平局并标 `stalled: true`，报告单列。
- 清 `log` 只清返回的状态，不碰引擎内部。
- 校验模式（`--verify`）额外做两件事：每步跑 `problemsOf` 不变量、每局用 `committed` 动作重放比对指纹。只用于抽查，日常跑批关掉。

## 10. 矩阵估计

- 每对角色：甲 3 套 × 乙 3 套 = 9 格。
- **自适应采样**：每格最多 400 局，打完 40 局后如果全是一边倒（全甲胜/全乙胜/全平），提前收手并标 `certain: true`。实测大量格子在第 1 局就定了，固定打 400 局是纯浪费。
- **共用种子集**：同一对的所有格子用同一批种子，便于配对比较（同样精度省一半以上局数）。
- **只跑上三角**：甲 vs 乙 与 乙 vs 甲 是同一批对局，矩阵转置即可，省一半算力。这条同时是自检项。
- 每格记三个数：甲胜、乙胜、平。主口径 `winA + 0.5·draw`，同时存原始三分量，平局率单独报。
- 置信区间用 Wilson 区间，不用正态近似（胜率贴边时正态区间会越界）。
- **对半复核**：每格按种子奇偶分两半，两半各判一次状态，不一致记 `underpowered`。早停后某一半可能为空，此时跳过该半、用全量结果，不硬判。

## 11. 训练循环

### 11.1 单位

一轮 = 固定乙，练甲；再固定甲，练乙。共 2 轮。

理由：双方同时练会互相追着改，转圈是搜索动力学，不是游戏结构。轮流练可避免这个假象；2 轮是因为每轮都在扩大对手历史库，收益递减，第 3 轮的提升预计小于噪声（P1 要实测验证，不能凭信）。

### 11.2 一代

```
对手池 F = 对方当前 3 套 + 对方历史库最近 3 套（按权重去重，最多 6 套）
  ↓
种群 = 3 个精英 + 变异孩子 + 随机新个体，共 12
  ↓
第一段：每个候选与 F 各打 6 局 → obj = 0.75·min + 0.25·mean
  ↓
按 obj 排序，取前一半（6 个）进第二段，各再打 16 局复核
  ↓
取前 3 作精英
  ↓
重复 4 代
```

两段评估是为了把局数花在真正有希望的候选上：第一段全局粗筛，第二段只给晋级者加样本。

### 11.3 目标函数

`obj(p) = 0.75 · min_F 胜率(p, q) + 0.25 · mean_F 胜率(p, q)`，平局按 0.5 计。

纯 maximin（只取最小值）会训练出只针对对手当前三套的偏科打法，对手一换就崩；掺四分之一平均胜率能把它拉回来。这也是 P1 增强改的：原来用纯 maximin，5 对里出现大量"任何打法都输"的塌缩。

不要只用平均胜率——那会训练出只欺负对手当前三套的策略，换一代对手就废。

### 11.4 变异

| 阶段 | 扰动幅度 | 说明 |
|---|---|---|
| 第 1–2 代 | ±0.20 | 粗调，允许换性格 |
| 第 3–4 代 | ±0.10 | 中调 |
| 第 5 代起 | ±0.05 | 细调 |
| 每代额外 | 10% 概率 ±0.40 | 大跳，防局部最优 |

每次变异：18 个权重各以 50% 概率被扰动，然后夹回 0–1。

### 11.5 历史库

每轮结束把该方的 3 套精英存进历史库，每方上限 9 套，进对手池时取最近 3 套。这样对手池始终包含"上一版打法"，防止新打法只针对当前版本。

### 11.6 降维（可选，未做）

18 个权重里可能只有少数几个真的影响结果。跑一次单因子扫描（每个权重单独扫 5 个值，其余固定），不敏感的权重锁死在中位。当前 18 维、种群 12、4 代还跑得动，等成本上来了再做。

## 12. 状态判定

### 12.1 输入

一对角色的 3×3 矩阵，每格含胜率、平局率、局数、Wilson 区间。

### 12.2 判据

顺序很重要：**先看策略有没有影响（极差），再看有没有鞍点**。反过来的话，一张全是 100% 的表会到处是鞍点，被判成"静止（有唯一最优打法）"——但那时任何打法都赢，不存在最优解。

```js
function label(M) {
  const spread = maxCell(M) - minCell(M);

  // 1. 策略无影响
  if (spread < 0.15) {
    // 一边倒 → 死局；五五开 → 策略无差别
    return mean(M) 偏离 0.5 >= 0.2
      ? { state: "静止", mode: "策略无关", strength: "强" }
      : { state: "开放", mode: "平坦" };
  }

  // 2. 有鞍点：格 (i,j) 同时是所在行的最小值与所在列的最大值
  const best = 最大 gap 的鞍点;
  if (best) {
    if (best.gap >= 0.10) return { state: "静止", mode: "唯一最优", strength: gap >= 0.25 ? "强" : "中" };
    return { state: "开放", mode: "弱鞍点" };   // 换招只值几个百分点，等于没有最优解
  }

  // 3. 无鞍点且策略有影响 → 克制循环
  return { state: "封闭" };
}
```

`gap` 是"该格胜率 − 甲其他打法的保底胜率"，衡量换打法能救回多少。

### 12.3 状态的四个子类

| 状态 | 子类 | 含义 |
|---|---|---|
| 静止 | 策略无关 | 任何打法都改不了胜负，一边倒的死局 |
| 静止 | 唯一最优 | 只有一套打法压住对手所有选择 |
| 静止 | 多重最优 | 几套打法并列最强，其余明显更差 |
| 封闭 | — | 没有必胜打法，但打法之间互相克制 |
| 开放 | 平坦 | 所有格子挤在 50% 附近 |
| 开放 | 弱鞍点 | 有鞍点但换招只值几个百分点 |
| 开放 | 单向 | 只有一方的选择能改变结果，另一方怎么打都一样 |

`resolve: underpowered` 单独表示"没测够"：前后两半种子判出的标签不一致，此时本体结论不可信。

### 12.4 判定器的自检

必须构造三个已知矩阵测一遍：

| 构造矩阵 | 期望 |
|---|---|
| `[[0.9,0.8],[0.3,0.4]]` | 静止，强 |
| `[[0.5,0.8],[0.8,0.5]]` 一类的猜拳结构 | 封闭 |
| 全部在 0.48–0.52 | 开放，flat |

判定器写错会静默给出看着合理的结论，这是最危险的一类 bug。

## 13. 并行（未做）

## 15. 输出

```
_local/strategy-lab/runs/<runId>/
  report.md          人读的汇总报告
```

产物放 `_local` 下：不进仓库，也不会被 `check.ps1` 的文件扫描算进去。

`verdicts.json` 一项：

```json
{
  "pair": ["王荣逸", "李硕"],
  "state": "静止",
  "strength": "强",
  "resolve": "solid",
  "stable": true,

  "spread": 0.71,
  "support": [1, 1],

  "tentative": null
}
```

`report.md` 内容顺序：

1. 一句话结论：几对静止、几对封闭、几对开放。
2. 总表：每对一行，状态、平均胜率、平局率、强度、稳定性。
3. 明细：每对的 3×3 矩阵，标出鞍点。
4. 策略清单：每角色每对手的最优策略，翻译成规则句子。
5. 盲区声明：结论只对本策略库成立；单挑看不到三方循环。

## 18. 风险与已知坑

| 风险 | 后果 | 处理 |
|---|---|---|
| 特征估算不准 | 练出的策略质量差 | 判定不受影响；标定表验收卡 25% 误差 |
| 对手策略集太小（3 套） | "静止"偏多 | 每对手 3 套，加历史库；报告标注策略数 |
| 拖平流策略 | maximin 下容易练出"不输" | 平局率单列，拖平率 > 20% 的对要人工看 |
| 搜索局部最优 | 覆盖不到更好打法 | 大跳变异、多随机起点、降维扫描 |
| 判定器写错 | 给出看起来合理的错结论 | 三个构造矩阵自检，必做 |
| `effectOps.valueOf` 是坏的 | 数值求值静默返回对象 | 走标定表，不碰这个导出 |
| 同时训练双方 | 假循环 | 轮流训练，禁用双侧同时优化 |
| 长局 | 拖慢跑批 | p90 4ms，最长 25ms，可接受；`--cap` 兜底 |

## 19. 开工前要定的四件事

1. 标定表要不要进版本管理。建议进（`data/calibration.json` 是生成物但稳定），换引擎版本时重算并对比。
2. 主口径用 `winA + 0.5·draw` 还是 `winA/(winA+winB)`。建议前者为主、后者并列输出。
3. 训练产物 `runs/` 要不要进版本管理。建议不进，只留 `report.md` 与 `verdicts.json` 进。
4. 是否允许为了标定给引擎加一个只读导出。建议不允许，用标定表。
