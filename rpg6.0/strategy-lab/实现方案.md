# 策略实验室 · 实现方案

状态：已实现并迭代五轮（R1 判定器 → R2 条件规则策略 → R3 双 oracle 循环 → R4 稳健性 → R5 定稿）。本文档是设计稿与演进记录；§8/§11/§12 已按实现更新，命令行、输出、验收与演进记录见 [实现方案-运行与演进.md](实现方案-运行与演进.md)。当前口径细节以 `lib/analyze.mjs`、`lib/train.mjs` 与 [使用说明.md](使用说明.md) 为准。

## 0. 一句话

给 N 个角色，每个角色为每个对手练出 3 套打分式打法，两两组合跑出胜率矩阵，再从矩阵上精确判定每对角色属于静止、封闭还是开放。

## 1. 实测基线（本机，2026-11-15）

| 指标 | 值 | 怎么量的 |
|---|---|---|
| 分析吞吐 | 339 局/秒/核 | 57 局，清空日志、不跑不变量、不跑重放 |
| 校验吞吐 | 25 局/秒/核 | `batch.mjs --pairs=smoke --seeds=1`（含每步不变量 + 每局重放） |
| 单局耗时 | p50 1.56ms / p90 4.26ms / max 25ms | 同上，长局 244 步 |
| 单局步数 | 平均 36 / 最长 244 | 同上 |
| 每决策候选动作 | 平均 4.04 / p90 5 / 最多 8 | 同上 |
| 角色 / 技能 | 19 / 67，引擎 `6.0-engine.7` | `rpg6.0/data/battle-skills.js`、`rpg6.0/data/config.js:8` |
| 逻辑核数 | 12 | `$env:NUMBER_OF_PROCESSORS` |
| 全流程成本 | 6 角色 15 对约 3.5 分钟（3 训练种子合并 + 8×8 终局矩阵 + 留出验证） | 本机实测（2026-11-17，R4 流水线） |

三条直接影响的结论：

1. **成本不是问题。** 之前按 25 局/秒估的成本高估了 13 倍。5 角色全流程（训练 + 矩阵）在 12 核上约 10 分钟，19 角色约 2 小时。
2. **打分函数只在 4 个选项里排序。** 每决策平均 4 个合法动作、最多 8 个。特征不用做得精细，权重也不用多。
3. **清日志安全且必要。** `state.hash`（`rpg6.0/js/engine/state.js:361`）不含 `log`，每步 `state.log.length = 0` 不影响判定、不影响重放，实测提速约 2 倍。

## 2. 目标与非目标

目标：

- 在本地直接调用引擎，不经页面、不经数据库。
- 每对角色得到一张胜率矩阵，并只从矩阵上判定静止 / 封闭 / 开放。
- 每个角色对每个对手的打法能翻译成人能读的规则句子。
- 结论带证据：样本量、置信区间、稳定性复核。

非目标：

- 不做自动改数值的平衡器。
- 不做页面、不做可视化（P4 之前）。
- 不追求策略空间的全局最优，只要求"证据覆盖到的范围内结论正确"。

## 3. 两条链路，不要混

| 链路 | 干什么 | 有误差吗 |
|---|---|---|
| A 训练 | 搜出 3 套好打法 | 有。启发式搜索，可能局部最优 |
| B 判定 | 从最终矩阵算状态 | 无。矩阵给定后是精确计算 |

误差只在"打法覆盖得够不够"，不在"状态算得对不对"。报告里要把这句话写进去。

## 5. 引擎接入

照 `_local/tests/engine/batch.mjs` 的方式，在 Node 里按序 require 引擎文件，再 require 技能库。第一个必须是 `version.js`（它设置 `B.ENGINE_VERSION`，标定表用它做版本校验）：

```
version → rng → rules → traits → state → damage → effect-ops → timeline
→ conditions → skills → summons → actions → battle
```

然后 `B.skills.load(globalThis.RPG6_SKILLS)`。

角色档案用 `vm` 在沙箱里读 `rpg6.0/data/characters.js`，取 `window.RPG_SEED_CHARACTERS`，再按技能库里的角色名过滤。

**不要**改引擎的加载顺序或模块路径，`battle.mjs` 依赖 `root.RPG6B` 这个全局。

## 7. 技能标定表

打分需要"这个动作能打多少伤害"，但不能复制引擎的伤害公式（会与引擎发散）。做法是**用引擎给引擎打表**：

1. 造一个固定假人对局：攻击方面板固定（atk 100，技能按角色原值），受击方 def 0、mres 0、hp 100000。
2. 对每条技能强制释放一次，读受击方血量差，得到基准伤害与段数。
3. 治疗的技能同法读回血量。
4. 结果写入 `data/calibration.json`，形如 `{ "liuwenzhe.xxx": { damage: 180, hits: 1, type: "phys", heal: 0 } }`。

运行时的伤害估计（**三种类型公式不同，不能统一按比例缩放**）：

| 类型 | 引擎公式 | 标定值含义 | 运行时 |
|---|---|---|---|
| 普伤 `phys` | `max(0, 攻击 − 防御)` | 假人 def=0，标定值就是攻击 | `max(0, 标定值 − 目标防御)` |
| 法伤 `magic` | `攻击 ÷ 100 × (100 − 法抗)` | 假人 mres=0，标定值就是攻击 | `标定值 ÷ 100 × (100 − 目标法抗)` |
| 真伤 `true` | `攻击` | 标定值就是伤害 | 不修正 |

`last`（按已损血算）与 `basic`（按面板算）是动态伤害，标定值只作参考，按真伤处理。

另外两类要特别标注：

- `delayed`：`tick` / `schedule` 这类延迟伤害，标定时当场伤害为 0，只记 `delayed: true`，打分时按"资源收益"处理，不按伤害处理。
- `mixed`：一条技能里同时有多个伤害类型（如庄文希的普伤+真伤），标定值是多段之和，无法拆开，按真伤估。

**注意**：`B.effectOps.valueOf` 实测是坏的——它等于 `Object.prototype.valueOf`（`effect-ops.js` 里 `api.valueOf = valueOf` 引用了未定义的 `valueOf`），调用后返回 `effectOps` 这个对象而不是数值。标定不要依赖它。若要走数值求值路线，需要在 `effect-ops.js` 补一个 `api.evalValue = evalValue` 的只读导出，按项目规矩这要升 `engineVersion` 并同步文档。**优先走标定表路线，不动引擎。**

## 8. 打分策略（R2 起：条件规则 DSL）

### 8.1 策略形状

```
策略 = { base: [6 权重], rules: [至多 4 条 { when: [条件…], w: [6 权重] }] }
```

`choose` 时自上而下找第一条全部条件命中的规则，用它打分；无命中用 `base`。旧 18 权重（3 档血量 × 6 特征）是本空间的真子集：`legacyPolicy` 把它转成 3 条按血量分档的规则，训练时作为种子个体保证不退化。

### 8.2 条件池（8 特征，全部能从引擎状态直接读出）

| 特征 | 取值 | 来源 |
|---|---|---|
| `selfHp` / `foeHp` | 血量档 hi/mid/lo | `tierOf`（≥60% / 30%–60% / <30%） |
| `foeTaunt` | true | `maxTauntUids(state, 敌方侧)` 非空 |
| `selfMp` | hi/lo | mp ≥ 蓝上限一半 |
| `round` | early/late | `state.round ≤ 2` |
| `foeLastAct` | attack/break/charge/skill | `play` 循环自记对方上一步 |
| `summonAlive` | true | `summonsOf(state, 我方侧)` 有存活 |
| `foeBreakNear` | true | `foe.breakValue ≥ breakValueMax − 1`（5 − 1） |

同一条规则内同一特征只出现一次（两个值互斥会成死规则）。

### 8.3 打分

6 维线性打分（与旧 §8.2 同式，去掉血量档位，档位由规则承担）：

```
score = w[0]·d + w[1]·k + w[2]·h + w[3]·g − w[4]·c − w[5]·x
```

特征来源与归一化同旧 §8.1（伤害/补刀/回血/资源/消耗/空转，标定表修正）。

### 8.4 变异与交叉

| 算子 | 说明 |
|---|---|
| 权重扰动 | base 与每条规则的权重各以 50% 概率 ±σ，夹回 0–1 |
| 条件翻转 | 随机一条规则的一个条件换取值 |
| 加规则 | 规则数 < 4 时加一条随机规则 |
| 删规则 | 随机删一条 |
| 换序 | 两条规则互换位置（顺序影响语义） |
| 交叉 | 前缀取父 A 规则、后缀取父 B 规则，base 随机取一方 |

算子按规则数可用性随机选（空规则集不会选到翻转/删除）。

### 8.5 可读翻译

规则 → 条件词 + 权重词：`对方有嘲讽且我方血量≥60%：伤害优先，回血最不看重`；无规则行翻译为 `默认：…`。

## 9. 单局执行

```js
function play(A, B, policyA, policyB, seed, cap = 400) {
  let state = RPG6B.battle.create({ seed, a: A, b: B }).state;
  let steps = 0;
  while (state.phase !== "finished" && steps < cap) {
    const list = enumerate(state);
    const side  = state.turnUid === state.units[0].uid ? "a" : "b";
    const pick  = choose(state, list, side === "a" ? policyA : policyB);
    state = RPG6B.battle.apply(state, pick).state;
    state.log.length = 0;
    steps += 1;
  }
  return {
    result: state.phase === "finished" ? state.result : "draw",
    stalled: state.phase !== "finished",
    steps,
    rounds: state.round
  };
}
```

要点：

- `cap` 默认 400（实测最长 244 步）。超限记平局并标 `stalled: true`，报告单列。
- 清 `log` 只清返回的状态，不碰引擎内部。
- 校验模式（`--verify`）额外做两件事：每步跑 `problemsOf` 不变量、每局用 `committed` 动作重放比对指纹。只用于抽查，日常跑批关掉。

## 10. 矩阵估计

- 每对角色：甲策略池 × 乙策略池（终局每侧至多 8 套，来自 3 个训练种子合并修剪）。
- **自适应采样**：每格最多 `--games` 局，打完 `--mingames` 局后如果全是一边倒（全甲胜/全乙胜/全平），提前收手并标 `certain: true`。实测大量格子在第 1 局就定了，固定打 400 局是纯浪费。
- **共用种子集**：同一对的所有格子用同一批种子，便于配对比较（同样精度省一半以上局数）。
- 每格记三个数：甲胜、乙胜、平。主口径 `winA + 0.5·draw`，同时存原始三分量，平局率单独报。
- 置信区间用 Wilson 区间，不用正态近似（胜率贴边时正态区间会越界）。
- **对半复核**：每格按种子奇偶分两半，两半各判一次状态，不一致记 `underpowered`。早停后某一半可能为空，此时跳过该半、用全量结果，不硬判。
- **Wilson 灵敏性**：每格用 Wilson 区间下/上端点各重判一次，与全量结论不一致记 `sensitive.stable: false`。
- **先手随机性**：引擎由种子决定谁先手（`state.rng & 1`），同一格不同种子窗口可以不同结果；`certain` 只对采样过的窗口成立，灵敏性是兜底。

## 11. 训练循环（R3 起：双 oracle / PSRO-lite）

### 11.1 一轮

```
初始种群各 start 套（legacy 分档种子 + 随机规则策略）
  ↓
循环 t = 1..oracles：
  对当前种群的经验矩阵（增量采样：新策略只补新行/新列）求均衡混合 (x, y, v)
  ↓
  甲方最佳回应：对 y 混合对手进化搜索（pop 候选 × brGens 代，现任最优做种子）
  乙方最佳回应：对 x 混合对手同理
  ↓
  gainA = BR_A 胜率 − v；gainB = BR_B 胜率 − (1 − v)；expl = gainA + gainB
  ↓
  expl < eps → 收敛停；双方 BR 都已在种群 → 停（br-dup）；种群到 maxPop → 停
  否则 BR 入池（按 policyKey 去重）
```

### 11.2 关键取舍

- 矩阵按策略对缓存，每轮只补新格，省掉重复局数。
- BR 的评估用**混合加权**（对手按均衡权重加权胜率），不是采样对手，无采样噪声。
- 候选共享种子集，配对比较更稳。
- 收敛判据 expl 只在 BR 搜索能力内成立：搜索太弱会假收敛（榨取值 0 但存在没找到的反制），实测 pop 10 × 5 代 + 现任种子能压住大多数对。
- 骰子噪声对（如于梓越×李硕）矩阵格与新鲜评估不一致，会停在 br-dup，榨取值非 0，报告如实标注。

### 11.3 多种子合并（R4 起）

同一对跑 3 个训练种子（baseSeed、+1000、+2000），策略池合并去重（上限 12），按「对敌方池的最差胜率」修剪到每侧 8 套，再做终局矩阵。单种子练出的结论是策略库相对的：不同种子各找到对方没有的好策略，合并才能凑齐互相克制的反制集（王荣逸×江雨轩的封闭结构只有合并后出现）。

## 12. 状态判定（R1 起：均衡口径）

### 12.1 输入

一对角色的 m×n 矩阵，每格含胜率、平局率、局数、Wilson 区间。

### 12.2 判据

顺序很重要：**先看策略有没有影响（极差近零），再看有没有纯鞍点，最后混合均衡**。反过来的话，一张全是 100% 的表会到处是鞍点，被判成"静止（有唯一最优打法）"——但那时任何打法都赢，不存在最优解。

```js
function label(M) {
  // 深度分：均衡面前纯策略打法的可榨取值
  depth = (列极小极大 − 行极大极小) / 2;   // 列极小极大 = min_j max_i M[i][j]，行极大极小 = max_i min_j M[i][j]

  // 1. 极差 < 0.05：策略选择几乎不改变结果
  if (spread < 0.05) {
    return 均值偏离 0.5 >= 0.2
      ? { state: "静止", mode: "策略无关" }
      : { state: "开放", mode: "平坦" };
  }

  // 2. 纯鞍点：格 (i,j) 同时是所在行最小值与所在列最大值
  if (有鞍点) {
    gap = 最好行保底 − 其余行里最好的保底;   // 并列最优不算第二名
    if (gap >= 0.10) return { state: "静止", mode: 唯一/多重最优, strength: gap >= 0.25 ? 强 : 中 };
    // 一方行保底全同 → 该方无选择
    return { state: "开放", mode: 弱鞍点 / 单向 };
  }

  // 3. 无鞍点 → 支撑枚举求混合均衡（无鞍点的零和矩阵必有双方支撑 ≥2 的均衡）
  return { state: "封闭", strength: depth >= 0.25 ? 强 : depth >= 0.10 ? 中 : 弱 };
}
```

`gap` 是"换打法能救回多少"；`depth` 是"混合均衡比纯策略值多少"。被严格支配（带 0.02 裕量）的行/列单列上报。

### 12.3 混合均衡求解（支撑枚举）

对每个非空行支撑 S × 列支撑 T，解 s+t 元线性方程组（行对 T 的无差异方程 + 列对 S 的无差异方程 + 两个归一化），校验权重严格为正与支撑外不等式：

- 列是极小化方：支撑外列 j 只有当行方收益 < v 才想偏离 → `val < v` 则无效。
- 行是极大化方：支撑外行 i 只有当收益 > v 才想偏离 → `val > v` 则无效。

取总支撑最小者。≤8×8 时 255×255 对支撑毫秒级。**这两个不等式方向写反时，满支撑矩阵测不出来，非对称矩阵才现形**（实测曾把 v=0.5 算成 1，回归用例见 selftest 的 5×4 矩阵）。

### 12.4 状态的七个子类

| 状态 | 子类 | 含义 |
|---|---|---|
| 静止 | 策略无关 | 任何打法都改不了胜负，一边倒的死局 |
| 静止 | 唯一最优 | 只有一套打法压住对手所有选择 |
| 静止 | 多重最优 | 几套打法并列最强，其余明显更差 |
| 封闭 | 强/中/弱 | 双方都要混合换招互相克制，深度分定强度 |
| 开放 | 平坦 | 所有格子挤在 50% 附近 |
| 开放 | 弱鞍点 | 有鞍点但换招只值几个百分点 |
| 开放 | 单向 | 只有一方的选择能改变结果，另一方怎么打都一样 |

`resolve: underpowered` 单独表示"没测够"：前后两半种子判出的标签不一致。`sensitive.stable: false` 表示 Wilson 区间端点重判结论翻转。

### 12.5 判定器的自检

构造矩阵回归集（selftest 里 11 个用例）：

| 构造矩阵 | 期望 |
|---|---|
| `[[0.9,0.8],[0.3,0.4]]` | 静止，强（鞍点 (0,1)，gap 0.5） |
| `[[0.5,0.8],[0.8,0.5]]` | 封闭，均衡值 0.65 |
| `[[0.55,0.45],[0.45,0.55]]` | 封闭（弱）——旧口径误判平坦的实锤 |
| `[[0.9,0.1],[0.1,0.9]]` | 封闭（强），深度分 0.4 |
| `[[0.9,0.9],[0.9,0.9]]` | 静止 · 策略无关 |
| `[[0.65,0.5],[0.65,0.5]]` | 开放 · 单向·甲方无选择 |
| 3×3 全循环 | 封闭，支撑 3/3，均衡值 17/30 |
| 非对称 5×4 / 3×2 | 均衡值 0.5（支撑外校验方向回归） |

判定器写错会静默给出看着合理的结论，这是最危险的一类 bug。

## 18. 风险与已知坑

| 风险 | 后果 | 处理 |
|---|---|---|
| 特征估算不准 | 练出的策略质量差 | 判定不受影响；标定表验收卡 25% 误差 |
| BR 搜索局部最优 | 假收敛（榨取值 0 但存在没找到的反制） | 现任种子 + pop 10 × 5 代 + 3 种子合并；报告如实标注 |
| 骰子噪声对 | 矩阵格与新鲜评估不一致，br-dup 停 | 榨取值非 0 如实标注；终局矩阵 400 局兜底 |
| 先手随机性 | `certain` 只对采样过的种子窗口成立 | Wilson 灵敏性标注 |
| 拖平流策略 | 练出"不输" | 平局率单列，拖平率 > 20% 的对要人工看 |
| 判定器写错 | 给出看起来合理的错结论 | 构造矩阵回归集 11 例，必做 |
| `effectOps.valueOf` 是坏的 | 数值求值静默返回对象 | 走标定表，不碰这个导出 |
| 同时训练双方 | 假循环 | 双 oracle 循环（对均衡混合求回应），禁用双侧同时优化 |
| 长局 | 拖慢跑批 | p90 4ms，最长 25ms，可接受；`--cap` 兜底 |

## 19. 开工前要定的四件事

1. 标定表要不要进版本管理。建议进（`data/calibration.json` 是生成物但稳定），换引擎版本时重算并对比。
2. 主口径用 `winA + 0.5·draw` 还是 `winA/(winA+winB)`。建议前者为主、后者并列输出。
3. 训练产物 `runs/` 要不要进版本管理。建议不进，只留 `report.md` 与 `verdicts.json` 进。
4. 是否允许为了标定给引擎加一个只读导出。建议不允许，用标定表。
