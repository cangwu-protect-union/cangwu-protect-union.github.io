# 策略实验室 · 使用说明

## 这是什么

一个本地跑的程序。它让引擎自己打自己：给几对角色各练几套打法，两两组合打很多局，统计胜率，最后告诉你每对角色属于哪种情况。不需要开网页，不需要登录。

## 现在能跑到什么程度

P1 已完成，可以跑出完整报告：

- 训练打法（18 个权重的进化搜索，按血量分三档，双方轮流练）
- 3×3 胜率矩阵（自适应采样，确定性对局提前收手）
- 状态判定（静止 / 封闭 / 开放，带子类）
- Markdown 报告 + 单文件 HTML 热力图 + JSON

还没做：站点页与数据库（P3）、PSRO 判定（P4）。

## 怎么跑

在工作区根目录执行：

```
node rpg6.0/strategy-lab/lab.mjs --chars=5
```

跑完在 `_local/strategy-lab/runs/<时间戳>/` 里出三份东西（产物不进仓库，不会被 check.ps1 扫）：

| 文件 | 看什么 |
|---|---|
| `report.html` | 双击打开，热力图 + 每对明细，可筛选状态 |
| `report.md` | 纯文本版，适合贴到别处 |
| `policies.json` | 全部打法参数与训练轨迹 |

5 角色 10 对约 2 分钟。

只跑一对：

```
node rpg6.0/strategy-lab/lab.mjs --pairs=王荣逸+李硕 --games=400
```

先自检，确认引擎接入和判定器没问题：

```
node rpg6.0/strategy-lab/selftest.mjs
```

## 参数

| 参数 | 默认 | 含义 |
|---|---|---|
| `--chars=5` | 5 | 取前几个角色参加（对数按平方涨） |
| `--roster=a,b,c` | 空 | 指定参加的角色 |
| `--pairs=A+B,C+D` | 空 | 只跑指定对，`+` 连接两个角色名 |
| `--strategies=3` | 3 | 每个角色保留几套打法，矩阵是 N×N |
| `--games=400` | 400 | 每格最多多少局 |
| `--mingames=40` | 40 | 自适应采样的最少局数；全一边倒就提前收手 |
| `--noadaptive` | 关 | 关掉早停，每格打满 `--games` |
| `--gens=4` | 4 | 练几代 |
| `--pop=12` | 12 | 每代候选数 |
| `--screen=6` | 6 | 第一段评估每格多少局 |
| `--confirm=16` | 16 | 第二段评估每格多少局 |
| `--rounds=2` | 2 | 轮流训练几轮 |
| `--cap=400` | 400 | 单局步数上限，超了算平 |
| `--seed=1000` | 1000 | 种子基准，换它等于换一批对局 |
| `--out=xxx` | `_local/strategy-lab/runs/<时间戳>` | 产物目录，相对工作区根 |
| `--recalibrate` | 关 | 强制重建技能标定表 |

## 输出怎么读

总表长这样：

| 对局 | 状态 | 平均胜率 | 平局率 | 强度 | 稳定性 | 极差 |
|---|---|---|---|---|---|---|
| 王荣逸 vs 刘文哲 | 静止（唯一最优） | 44.4% | 0.0% | 强 | 稳定 | 1 |
| 王荣逸 vs 王泺然 | 静止（无策略差异） | 0.0% | 0.0% | 强 | 稳定 | 0 |
| 刘文哲 vs 李硕 | 开放（弱鞍点） | 44.4% | 0.0% | — | 稳定 | 1 |

- **平均胜率**：左边角色在矩阵所有格子的平均胜率。
- **平局率**：到步数上限没分胜负的比例。
- **极差**：矩阵里最高胜率减最低胜率。极差 0 就是"换打法结果不变"。
- **强度**：静止时才有，强 = 换打法能拉开 25 个百分点以上。
- **稳定性**：样本对半分，两半分别判一次，一致才算稳定。

每对后面有一张 3×3 明细表，格子里是甲的胜率，鞍点标 ★。最后是双方每套打法的三档规则。

## 状态怎么理解

| 状态 | 子类 | 含义 | 设计含义 |
|---|---|---|---|
| 静止 | 唯一最优 | 有一套打法压住对手所有选择，换别的会掉 | 死局，选人即定胜负 |
| 静止 | 多重最优 | 有几套并列最强，其余明显更差 | 有最优解，但不止一个入口 |
| 静止 | 无策略差异 | 任何打法都改不了胜负，一边倒 | 死局，纯粹角色强度 |
| 封闭 | — | 没有必胜打法，打法之间互相克制 | 猜拳结构，通常最耐玩 |
| 开放 | 平坦 | 所有格子挤在 50% 附近 | 策略维度不出信息 |
| 开放 | 弱鞍点 | 有最优打法，但换招只值几个百分点 | 最优解存在但不值得算 |
| 开放 | 单向 | 只有一方的选择能改变结果 | 另一方是"陪打"，深度不对称 |

另外有个 `预算不足` 标记：前后两半种子判出的结论不一致，说明样本不够，此时结论不可信。

## 常见问题

**全是静止，没有封闭。**
先看"极差"列。极差为 0 的对是策略真的没用；极差为 1 的对是有一边明显更强。封闭要求"没有哪个打法能压住全场，但打法之间互相赢"——这需要双方都有多个势均力敌又能互相针对的选项。当前每个角色只有几套权重打法，动作又少，很难形成这种结构。

**结论和我想的不一样。**
先看"保底 vs 随机"那一列（在 Markdown 报告里）：接近 0% 说明训练把打法练废了，那一对不可信。再看极差：极差 0 的对，胜率只反映角色强度。

**为什么有的对局只打了 40 局？**
自适应采样：打到 40 局如果全是一边倒，就提前收手，标"确定性"。引擎很多对局是确定性的，同一套打法打多少次结果都一样。

**能改角色数值吗？**
不能。这个工具只读引擎数据。要平衡角色先改 `battle-skills.js`，再重跑。

## 边界

- 结论只对本次训练出的那几套打法成立，换策略库结论会变。
- 只看单挑，三方克制循环测不出来。
- 判定先看"策略有没有影响"（极差），再看鞍点。极差为 0 时不会判成"有最优打法"。
