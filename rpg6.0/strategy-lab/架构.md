# 策略实验室 · 架构

本文只讲结构与数据流。算法细节见 [实现方案.md](实现方案.md)，使用方式见 [README.md](README.md)。

## 一、三条链路

```
① 计算（本机 Node，不进站点）
   角色表 ─▶ 训练 ─▶ 矩阵 ─▶ 判定 ─▶ run.json / report.*
                              │
② 存储                        ├─▶ 快照 data/lab-snapshot.js（随站点发布，兜底）
                              └─▶ 数据库 rpg_lab_runs + rpg_lab_pairs（历史，需要令牌写）

③ 展示（静态站点）
   lab.html ─▶ 读数据库（失败/为空）─▶ 读快照 ─▶ 渲染矩阵
```

三条链路只有 `run.json` 一个契约。计算层不依赖站点，展示层不依赖 Node。

## 二、计算层模块

| 模块 | 职责 | 依赖 |
|---|---|---|
| `lib/engine.mjs` | 按序加载 13 个引擎文件与技能库，读角色表 | 无 |
| `lib/enumerator.mjs` | 枚举合法动作（嘲讽、召唤物、数值档位） | 引擎 |
| `lib/calibration.mjs` | 用引擎结算给 67 条技能打表，生成 `data/calibration.json` | 引擎 |
| `lib/policy.mjs` | 18 权重（3 档血量 × 6 特征）打分、变异、规则翻译 | 标定表 |
| `lib/battle.mjs` | 单局执行、行为签名 | 枚举器、策略 |
| `lib/matrix.mjs` | 3×3 矩阵、自适应采样、Wilson 区间 | 单局 |
| `lib/train.mjs` | 轮流训练、对手池、两段评估、多样性选择 | 策略、矩阵 |
| `lib/analyze.mjs` | 极差 → 鞍点 → 子类，对半复核 | 无（纯数据） |
| `lib/report.mjs` / `lib/report-html.mjs` | Markdown 与单文件 HTML | 无（纯数据） |
| `lab.mjs` | 命令行、编排、导出快照 | 以上全部 |

关键边界：**训练与判定互不知道对方**。训练只产出权重，判定只吃矩阵。所以换掉训练算法（例如 PSRO）不影响判定与展示。

## 三、数据契约

### Policy

```json
{ "id": "王荣逸.vs.李硕.0", "w": [18 个数], "obj": 0.66, "min": 0.52,
  "signature": "9f2c1a3b", "readable": ["血量≥60%：伤害优先", "…"] }
```

### Matrix

`cells[i][j] = { n, a, b, d, certain, halves: [{n,a,b,d}, {n,a,b,d}] }`，`a` 是行方胜场，`d` 是平局。

自适应采样：打到 `minGames` 局后全一边倒就标 `certain` 提前收手。

### Verdict

```json
{ "state": "静止", "mode": "唯一最优", "strength": "强", "resolve": "solid",
  "stable": true, "spread": 1, "gap": 0.5, "cell": [0, 0], "support": [2, 3],
  "halves": ["静止", "静止"] }
```

`state` 三选一，`mode` 区分五种形态（策略无关 / 唯一最优 / 多重最优 / 平坦 / 弱鞍点 / 单向），`resolve` 标记 `underpowered`。

### Run

`run.json` 是上面三者的集合，加 `engineVersion`、`chars`、`config`、`generatedAt`。上传脚本和快照导出都只读这一个文件。

## 四、可替换点（留给后续会话）

| 位置 | 现在 | 可换 |
|---|---|---|
| `policy.mjs` 的 `choose` | 线性打分 + 三档血量 | 条件规则树、行为树、PSRO 混合策略 |
| `train.mjs` 的 `trainPair` | 进化 + 对手池 | 用 PSRO / MCTS 标注替换，保持返回 `{ a: Policy[], b: Policy[] }` |
| `analyze.mjs` 的 `classify` | 极差 + 鞍点 | 支撑枚举 / 线性规划求均衡，保持返回 Verdict |
| 存储 | 两张表 + 快照 | 加 `note`、赛季标签、差分对比 |

只要 `run.json` 的结构不变，页面和上传脚本都不用动。

## 五、与站点、数据库的边界

- 站点 `lab.html` **不跑任何对局**。计算全部在成员本机，避免静态站承担算力。
- 读库公开（`using (true)`），写库要 `gui_token_ok()`，令牌走 `Prefer: gui-token=...`（网关只放行这个头）。
- 快照是兜底，不是第二数据源：有数据库记录时页面优先显示数据库，快照只补最后一条。
- `_local/` 永不推送；SQL、运行产物都在里面。

## 六、失败模式

| 现象 | 原因 | 处理 |
|---|---|---|
| 跑批报"标定表引擎版本不符" | 引擎升版没重建标定 | `--stage=calibrate` |
| 页面显示"内置快照" | 数据库没建表 / 网络断 / 无运行记录 | 跑 SQL 迁移或上传一次 |
| 页面一直"正在读取…" | 网关冷启动 TLS 慢（实测 12 秒） | 等一次，或刷新；读超时 6 秒后自动退回快照 |
| 上传 42501 | 令牌过期（2 小时） | 重新取令牌 |
| 上传 404 `PGRST205` | 表没建或 schema cache 没刷新 | 执行迁移 SQL，脚本结尾有 `notify pgrst` |
