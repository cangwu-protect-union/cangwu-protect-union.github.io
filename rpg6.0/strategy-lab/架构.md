# 策略实验室 · 架构

本文只讲结构与数据流。算法细节见 [实现方案.md](实现方案.md)，使用方式见 [README.md](README.md)。

## 一、三条链路

```
① 计算（本机 Node，不进站点）
   角色表 ─▶ 训练 ─▶ 矩阵 ─▶ 判定 ─▶ run.json / report.*
                              │
② 存储                        ├─▶ 快照 data/lab-snapshot.js（随站点发布，兜底）
                              └─▶ 数据库 rpg_lab_runs + rpg_lab_pairs（历史，需要令牌写）

③ 展示（静态站点）
   lab.html ─▶ 读数据库（失败/为空）─▶ 读快照 ─▶ 渲染矩阵
```

三条链路只有 `run.json` 一个契约。计算层不依赖站点，展示层不依赖 Node。

## 二、计算层模块

| 模块 | 职责 | 依赖 |
|---|---|---|
| `lib/engine.mjs` | 按序加载 13 个引擎文件与技能库，读角色表 | 无 |
| `lib/enumerator.mjs` | 枚举合法动作（嘲讽、召唤物、数值档位） | 引擎 |
| `lib/calibration.mjs` | 用引擎结算给 67 条技能打表，生成 `data/calibration.json` | 引擎 |
| `lib/policy.mjs` | 条件规则策略（默认权重 + ≤4 条「8 特征条件→权重」规则）、变异/交叉、规则翻译 | 标定表 |
| `lib/battle.mjs` | 单局执行、行为签名、传递「对方上一步动作」上下文 | 枚举器、策略 |
| `lib/matrix.mjs` | 单格采样（自适应早停）、胜率矩阵、Wilson 区间 | 单局 |
| `lib/train.mjs` | 双 oracle 循环（PSRO-lite）：经验矩阵求均衡混合 → 双方进化最佳回应 → 按可榨取值收敛 | 策略、矩阵、均衡 |
| `lib/analyze.mjs` | 支撑枚举混合均衡、极差→鞍点→均衡判定、深度分、Wilson 灵敏性 | 无（纯数据） |
| `lib/report.mjs` / `lib/report-html.mjs` | Markdown 与单文件 HTML | 无（纯数据） |
| `lab.mjs` | 命令行、3 种子合并策略池、修剪、编排、导出快照 | 以上全部 |

关键边界：**训练与判定互不知道对方**。训练只产出策略池与均衡混合，判定只吃矩阵。换掉训练算法不影响判定与展示。

## 三、数据契约

### Policy

```json
{ "id": "王荣逸.vs.李硕.0",
  "w": { "base": [6 个数], "rules": [{ "when": [{ "f": "foeTaunt", "v": true }], "w": [6 个数] }] },
  "obj": 0.66, "min": 0.52, "signature": "9f2c1a3b",
  "readable": ["对方有嘲讽：伤害优先，…", "默认：…"] }
```

### Matrix

`cells[i][j] = { n, a, b, d, certain, halves: [{n,a,b,d}, {n,a,b,d}] }`，`a` 是行方胜场，`d` 是平局。

自适应采样：打到 `minGames` 局后全一边倒就标 `certain` 提前收手（注意：只对采样过的种子窗口成立，先手顺序有种子随机性）。

### Verdict

```json
{ "state": "封闭", "mode": "封闭", "strength": "强", "resolve": "solid",
  "stable": true, "spread": 1, "gap": null, "cell": null,
  "value": 0.5, "depth": 0.5, "support": [2, 2],
  "dominated": { "rows": [], "cols": [] },
  "sensitive": { "lo": ["封闭","封闭"], "hi": ["封闭","封闭"], "stable": true },
  "halves": ["封闭", "封闭"] }
```

`state` 三选一；`depth` =（列极小极大 − 行极大极小）/2；`sensitive` 是 Wilson 区间端点重判结果。

### Run

`run.json` 是上面三者的集合，加 `engineVersion`、`chars`、`config`、`generatedAt`、每对的 `meta`（均衡混合、种子数、可榨取值、收敛原因）。上传脚本和快照导出都只读这一个文件。

## 四、可替换点（留给后续会话）

| 位置 | 现在 | 可换 |
|---|---|---|
| `policy.mjs` 的规则 DSL | 条件规则表 + 进化搜索 | 状态抽象 + CFR / 后悔最小化，或带前瞻的值函数策略 |
| `train.mjs` 的 `trainPair` | 双 oracle 循环（PSRO-lite） | 更强的 BR oracle（MCTS 标注），保持返回策略池 + 均衡混合 |
| `analyze.mjs` 的 `nashOf` | 支撑枚举（≤8×8） | 更大矩阵用 LP / simplex，保持返回 `{ S, T, x, y, v, pure }` |
| 元博弈层 | 无 | alpha-rank 全角色排序 + 三角循环检测（吃多对矩阵） |
| 存储 | 两张表 + 快照 | 加 `note`、赛季标签、差分对比 |

只要 `run.json` 的结构不变，页面和上传脚本都不用动。

## 五、与站点、数据库的边界

- 站点 `lab.html` **不跑任何对局**。计算全部在成员本机，避免静态站承担算力。
- 读库公开（`using (true)`），写库要 `gui_token_ok()`，令牌走 `Prefer: gui-token=...`（网关只放行这个头）。
- 快照是兜底，不是第二数据源：有数据库记录时页面优先显示数据库，快照只补最后一条。
- `_local/` 永不推送；SQL、运行产物都在里面。

## 六、失败模式

| 现象 | 原因 | 处理 |
|---|---|---|
| 跑批报"标定表引擎版本不符" | 引擎升版没重建标定 | `--stage=calibrate` |
| 页面显示"内置快照" | 数据库没建表 / 网络断 / 无运行记录 | 跑 SQL 迁移或上传一次 |
| 页面一直"正在读取…" | 网关冷启动 TLS 慢（实测 12 秒） | 等一次，或刷新；读超时 6 秒后自动退回快照 |
| 上传 42501 | 令牌过期（2 小时） | 重新取令牌 |
| 上传 404 `PGRST205` | 表没建或 schema cache 没刷新 | 执行迁移 SQL，脚本结尾有 `notify pgrst` |
