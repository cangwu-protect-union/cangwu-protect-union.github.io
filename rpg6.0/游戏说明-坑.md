## 十、坑（都真实踩过）

1. `state.seed` 必须是**原始种子**；存混淆后的 rng 值会让回放从第一步发散。
2. 战报存 `committed` 动作；点技能蓄力不足时动作会被归一化成 `charge`。
3. `set` 不会清掉已有的 `add`，要做上限就加「差值」。
4. 回合制效果的 `unit` 是 `selfRound` / `targetRound`，不是 `"turn"`。
5. 状态/Buff 事件要带 `label`，否则界面显示内部 kind（如 `noDeath`）。
6. 标记必须先声明，没声明时 op 静默返回。
7. 技能条件与档案不一致会被禁用——这是校验，不是 bug。
8. 改规则要同时升 `data/config.js` 的 `engineVersion`，旧战报才会被标成旧引擎。
9. `docgen` 只扫模块根下的 `js/*.js`，`js/engine`、`js/battle` 不进架构图，说明写在 `架构.md` 手写区。
10. 技能禁用时只有「不是他的回合」才拦截点击；条件不满足（缺蓝、层数不够）要放行点击并给出原因。
11. 紧凑布局的断点必须写 `(orientation: landscape) and (max-height: 520px)`。只写 `max-width: 900px` 会把 844×390 的手机横屏也当成单列竖排——这是老版在手机上要滑三屏的原因。
12. 遮罩的显示条件不只看 CSS：JS 判 `(pointer: coarse)` + `maxTouchPoints > 0` + 视口短边 ≤520，命中才给 `<html>` 加 `is-phone`，CSS 只在 `is-phone` + 竖屏时显示遮罩。只写媒体的 `(pointer: coarse)` 会把触屏笔记本、平板也算进来。测遮罩要经 CDP `Emulation.setDeviceMetricsOverride({mobile:true})` + `setTouchEmulationEnabled`，`setViewportSize` 不改 pointer 与触摸点数。
13. 紧凑布局下 `.bq-skills` 自己滚、`.bq-actions` 固定在卡片底部；否则展开技能效果会把「普攻/击溃/蓄蓝」顶出可见区。
14. 伤害记录浮层用绝对定位，靠 `.battle-unit { overflow: visible }` 才能盖出卡片；改回 `auto` 会被裁掉。高度由 `applyLogPanel()` 现算：`max-height` 取「卡片底边 → 底栏顶边」，`min-height` 至少盖到技能卡底边，否则半行技能文字会露在浮层下面。不要写死 `vh`。
15. 折叠面板用原生 `<details>`，`open` 状态存在 `speedOpen` / `battleLogOpen` 里，每次 `render()` 重建 DOM 后按它恢复；直接读 DOM 会在下一次 render 丢状态。战斗日志由 `renderBattleLog(state, open, collapsible)` 决定输出：`collapsible` 为假时渲染成 `<section>`（桌面常显），为真才输出 `<details>`。
16. 测浮层的用例不能先注入行再点开：点开会触发 `render()` 重建 DOM，注入的内容会被冲掉，必须先点开再塞行。
17. 手机横屏的展开态统一用 `position: fixed; inset: 0` 铺满视口；面板里的 `<summary>` 要 `position: sticky` 顶住，否则长日志滚下去就没有关闭入口了。这些规则只写在紧凑断点里，别提到全局——桌面一旦被卷进去，战斗日志会变成盖住整页的浮层。
18. 受击掷骰免疫不能写成 `beforeDamage` 钩子：那条路径在 `noReaction`（江雨轩「肥肥反弹」的反弹伤害、被动强制普攻）时会跳过，毛毛就挡不住这些伤害。它走 `damage.hit` 最前面的 `skills.rollDodge`，与钩子无关；`buffImmune` 同理走 `skills.immuneBuffs`，在 `addBuff` 里拦截。
